# Beacon 開發規則

## 專案結構

- 專案根目錄：`C:\Users\User\Desktop\Beacon`
- Flask 後端：`server.py`
- 前端頁面：`index.html`
- 前端樣式：`style.css`
- 前端邏輯：`script.js`
- Python 套件：`requirements.txt`
- 環境變數：`.env`
- 啟動指令：`python server.py`
- 本機網址：`http://127.0.0.1:5000/`

## 安全規則

- 禁止讀取、顯示、複製或修改 `.env`。
- 禁止把 API Key、Token 或其他密鑰寫入前端檔案。
- 禁止把密鑰輸出到終端、日誌、回覆或測試結果。
- 除非任務明確要求，禁止刪除使用者資料或清空 `localStorage`。
- 修改前先確認現有功能與資料結構。

## 修改原則

- 優先採用最小修改。
- 不主動重構與任務無關的程式。
- 不自行增加使用者沒有要求的功能。
- 保留現有 Session、聊天、問題、診斷與歷史紀錄功能。
- 小型 UI 修改只處理必要的 HTML 或 CSS。
- 跨前端、後端、資料結構與 AI Prompt 的大型功能必須分階段完成。
- 不要在同一輪同時處理 UI、狀態機、後端、資料保存與完整測試。

## 任務規模

### 小修改

適用於：

- 文案
- 顏色
- 間距
- 尺寸
- 單一 CSS 問題
- 移除重複元素

規則：

- 驗收條件約 3～6 條。
- 不啟動不必要的後端或 API 測試。
- 只修改指定檔案。

### 中型修改

適用於：

- 新增一個面板
- 新增一段互動
- 調整單一 Session 流程
- 新增一組 localStorage 欄位

規則：

- 驗收條件約 8～15 條。
- 明確限制修改檔案。
- 只測試受影響的流程。

### 大型功能

適用於：

- 新資料結構
- 多問題系統
- 學習檔案
- 技能樹
- 跨前後端重構

規則：

1. 先分析現有架構，不修改檔案。
2. 拆成多個階段。
3. 每一階段只處理一種工作：
   - 資料結構
   - 功能邏輯
   - UI
   - 錯誤處理
   - 測試
4. 不直接一次完成全部功能。

## Beacon 產品結構

- 歷史紀錄：保存完整學習 Session 與聊天過程。
- 學習檔案：AI 整理後的永久學習資料。
- 學習成果：永久累積的技能樹與能力進度。
- 學習設定：只影響目前 Session。
- 系統設定：目前只包含 AI 模型選擇。

以上模組必須彼此獨立，不可共用或互相覆蓋資料。

## 學習空間規則

- 學習空間採聊天式介面。
- Session 資訊列使用淡灰半透明背景。
- AI 訊息左上角顯示訊息性質。
- 問題卡保留在原始聊天流中，不得移除。
- 尚未作答問題可在聊天輸入區上方以圓形 icon 顯示。
- 點擊問題 icon 可展開簡化作答區。
- 問題卡、icon 與簡化作答區必須共用同一個 `question_id`。
- 送出答案後，對應 icon 立即消失。
- 診斷期間只鎖定輸入與送出，不得封鎖聊天內容的捲動與查看。
- AI 不應每輪都自動出題。
- 「下一步」不等於「下一題」。
- AI 每次回覆只執行一個主要教學動作。

## 新 Session 流程

1. 顯示「今天想學些什麼？」
2. 使用者設定：
   - 科目
   - 主題
   - 學習目標
   - 學習階段
   - 目前程度
   - 教學方式
   - 預計時間
3. AI 先提供開場訊息。
4. 只建立一次初始評估。
5. AI 根據回答決定：
   - 解釋
   - 提示
   - 診斷
   - 出題
   - 總結
6. 不連續自動出題。

## 視覺規則

- Beacon 主品牌色為橘色。
- 品牌橘使用較沉穩的琥珀橘，不使用高亮螢光橘。
- 建議主色：`#D97721`
- 建議 hover：`#BF6418`
- 建議 active：`#A95212`
- 背景使用暖白、近白與中性灰。
- 文字使用黑色或深灰。
- 不使用大面積高飽和色塊。
- Session 資訊列維持淡灰半透明。
- AI 訊息卡維持白色或淡暖灰。
- 問題卡以中性色為主，只用橘色作局部強調。
- 取消與次要按鈕維持中性灰。
- 不得產生水平捲動條。

## Logo 規則

- Logo 檔案：`Beacon.png`
- 展開側欄時顯示完整 Beacon Logo。
- 收合側欄時只顯示燈泡圖示或裁切後 icon。
- Logo 不得變形。
- 不得同時顯示兩個重複的 `Beacon` 文字。

## 測試規則

- 純文案：不需啟動後端。
- 純 CSS：檢查語法與頁面外觀。
- JavaScript 互動：檢查語法並測試受影響操作。
- API 修改：啟動後端並測試相關端點。
- 跨檔案功能：最後再執行完整流程測試。
- 不為小修改執行不必要的完整回歸測試。
- 測試完成後，不要留下占用連接埠的臨時程序。

## 回報格式

完成任務後只回報：

1. 修改了哪些檔案。
2. 完成了哪些變更。
3. 執行了哪些必要測試。
4. 是否仍有未完成或不確定之處。

不要長篇重述原始需求。
